# Core

Row `binnacle` · Code `binnacle:packages/binnacle/src/index.ts#apply` · Intent: none yet

The core is not a feature that a person turns off: it owns the terminal, and every feature needs it.

## What a person can do

- Start binnacle with `dsh --profile binnacle`. It opens the Chat on a new session.
- Open a stored session with `dsh --profile binnacle --session <id>`. It is drawn, and nothing can be sent to it.
- Scroll the Place under the pointer with the wheel.
- Keep their place in a Place that follows a cursor, such as a List's: its view moves only as far as the cursor needs. The transcript keeps its Marked event's header on the top row.
- Suspend binnacle with ctrl+z, and come back to it.
- Get the terminal back as it was when binnacle exits, crashes or is suspended. What other code wrote while binnacle drew is written after, in order.

## What an author can change

- The Chat's layout: `binnacle.layout('chat', …)` replaces its tree of Places, so the composer can go on top or a Place can be added. The Chat's own Layout is exported as `CHAT_LAYOUT`, to build on.
- A Layout set by a name of their own, with `binnacle.layout(name, …)`, which a `{ layout: name }` node draws.
- One node of a Layout or Screen, and the rest kept: `binnacle.edit(name, edit)` inserts a node beside an anchor, moves the anchor's node beside another, removes the anchor's node, or replaces it. Two plugins that edit one Layout both apply, whichever loads first.
- The other nodes: `{ first: [...] }` draws its first child that has a line to draw, and `{ over, float, at }` draws a float on top of what it covers.
- A row of one line: `separator: true` joins the first line of each child by the theme's `divider` glyph, as the status line does.
- On any node: `unless: name` hides it while the Layout or the Place by that name has a line to draw, and `mouse: false` makes a click and the wheel inside it do nothing. `clickFocus: false` lets a click inside it act, and move no Focus.
- A Screen of their own: `binnacle.show(…)`.
- What a Place draws: `binnacle.place(name, part)`; the newest Part wins.
- Anything a built-in row registers: what an author registers ranks above it, whichever loads first.
- What a built-in's action does: set an action of its id. An action with no `keys`, `kind`, `place` or `first` keeps those of the action it hides. So it takes a gesture only where that action did ([Gestures](gestures.md)).
- Which keys run an action: `binnacle.bind(name, keys)` takes a list of keys, which replaces the action's, or a function of the keys beneath it, read at each gesture, which adds to keys that an action set later gives ([Gestures](gestures.md)).
- A node's size: `'fill'`, `'content'`, `{ fixed: n }`, or `{ most: n }`, what its lines need, up to `n` cells with its box. A Place taller than that scrolls in it.
- A Place's box: padding, gap, borders, a title, and an edge style by name.
- How a Place follows its Part's cursor: `follow` on the Part, `'end'` or `'least'`.
- Where the Focus was last moved, by a person or an author, on the Screen on view: `binnacle.focusMovedLast()`.
- How many of a Part's lines its Place shows now: `binnacle.linesShown(place)`, a wrapped line counted once, or `undefined` while the Place is not drawn.
- A composer of their own: the editor that the composer draws is exported as `Editor`, with `EditorTheme` and its cursor's mark `CURSOR_MARKER` ([Composer](composer.md)).
- A time that changes while it is drawn: the core's model `clock`, read with `binnacle.modelOf('clock')`, holds `now`, the time in epoch milliseconds. A Part or a Look that names it in its `models` is drawn again each second while it reads it.
- When the turn that runs started: the core's model `turn`, read with `binnacle.modelOf('turn')`, holds `startedAt`, in epoch milliseconds, or `undefined` while the agent does not run. With `clock`, a Look shows how long the turn has run.

- A test of their change, with no terminal: `mount` from `binnacle/testing` loads the built-ins and their plugins as a profile does, on a fake agent and a fake clock, and gives the screen as rows ([ADR 4](../adr/0004-an-author-needs-only-what-binnacle-exports.md)).

The author API is `binnacle:packages/binnacle/src/api.ts#Binnacle`, exported from binnacle's entry with `toPlainText`, `CHAT_LAYOUT`, `Editor` and `CURSOR_MARKER`.

## How it is built

- **A feature is a Cordis plugin on the `binnacle` service** ([ADR 1](../adr/0001-a-feature-is-a-cordis-plugin-on-the-binnacle-service.md)). The core is one row, and each feature is a row of its own, which a person turns off in their profile's patch.
- **An author needs only what binnacle exports** ([ADR 4](../adr/0004-an-author-needs-only-what-binnacle-exports.md)). A built-in imports only binnacle's entry, another built-in's entry, cordis and dsh's packages, and `binnacle:scripts/check-plugins.mjs#findInternalImports` fails `pnpm test` on any other import from `packages/binnacle/src/plugins/`. Each name that a built-in sets or reads, a Place, a Look, an action, a model or a Layout, is in AUTHORING.md: `binnacle:scripts/check-names.mjs#namesInSource` reads each one that a built-in's source gives, on every branch, and `binnacle:scripts/check-names.mjs#namesAtRuntime` records each one as `binnacle/testing` runs the built-ins through the states that reach each piece. A name is named by the guide as written, by a pattern of its namespace such as `transcript.tool.<name>`, or as a named instance's piece, `<name>.row`.
- **A Screen is a layout tree of named Places** ([ADR 2](../adr/0002-a-screen-is-a-layout-tree-of-named-places.md)). The Chat's tree is `binnacle:packages/binnacle/src/core/chat.ts#CHAT_LAYOUT`, frozen, as an author builds on it: the transcript fills, then the Layout `status` that the status line sets, the Layout `request` that the Requests' view sets, and the Layout `composer` that the composer sets take what their lines need. The composer is `unless: 'request'`, so a Request stands in its spot. The Chat's Focus starts in `composer.input`, the composer's Place. `binnacle:packages/binnacle/src/core/layout.ts#arrange` lays it out; a terminal too small gives up padding, gaps and borders before it cuts rows. A node that takes what its lines need, with less room than that, first shrinks the nodes in it that fill, down to none: the screen is too small only when what does not fill is cut. In a column, the nodes that fill share the rows left by need: each takes no more than its lines need while another needs more, the fewest first, and what is left after is shared evenly. So a Request's short question stays whole above many Choices, and its rule stays.
- **A Layout's tree is grown before each draw** (`binnacle:packages/binnacle/src/core/tree.ts#grow`). Each `{ layout: name }` node holds the newest Layout set by that name, and each node knows its size. A node with no size fills in a Screen's own Layout, and takes what its lines need in a Layout set by name. A Layout that draws itself, at any depth, draws nothing the second time.
- **A node of `{ most: n }` takes what a node of `'content'` takes, up to `n` cells** (`binnacle:packages/binnacle/src/core/tree.ts#wantedOf`). Its parent counts it so when it measures what its lines need and when it shares its cells, so a named Layout of `{ most: n }` is at most `n` high. A node of a fixed size counts as its size, and the others as what they need. A node of `{ most: n }` is short of room only when it gets fewer cells than the lesser of `n` and what it needs.
- **Edits apply to a Layout each time it is read for a draw** (`binnacle:packages/binnacle/src/core/edit.ts#edited`): to the newest Layout set by a Screen's name, or the Screen's own, and to the newest set by a name that a `{ layout: name }` node draws. An anchor is the name in a node's `place` or `layout`. An edit looks for it depth first, through rows, columns, `first`, `over` and `float`, children in order and `over` before `float`, and takes the first node found. It does not look inside a named Layout that the Layout draws. An edit whose anchor is not there does nothing, so it applies again when the anchor comes back.
- **The order of edits never depends on load.** Inserts apply, then moves, then replaces, then removes. Within each kind, a built-in's apply before an author's, as a registration ranks. Then they go by the plugin's own `name`, read from its Cordis fiber, with no name first, then by the edit's JSON text, each compared by code unit. A replace or a remove finds its anchor in the Layout as set, a moved node in its old place, so that of two nodes by one name the first is still the one found. It acts where a move put that node, on what stands in that node's place: of two replaces, the last holds, and a remove after a replace takes out what the replace put. An insert finds its anchor in the Layout as set, then in the nodes that inserts added, in the order they were added. Inserts apply in rounds until a round adds nothing, so an insert beside a node that another insert adds applies whichever sorts first. Inserts beside one anchor keep the order of edits, even when one waited a round for its anchor: after it, the first is next to it, and before it, the last is. An insert is drawn only where its anchor's parent is a row, a column or a `first`. A move takes the node of its first anchor, with its box, out of its place, and puts it beside its second, as an insert of that rank would go. It finds both anchors as an insert does, a moved node in its old place, and does nothing while either is not there, or while the second's parent is not a row, a column or a `first`. What inserts put beside the moved node stays in the old place. A removed root, `over` or `float` draws as an empty column.
- **A separated row draws one line** (`binnacle:packages/binnacle/src/core/separated.ts#cut`). A row with `separator: true` draws each child at its whole width, with no size and no box, and takes the child's first line: a Part's first line from `lines(width)`, before the core wraps it, or a nested node's first drawn row. A child with no line, or an empty one, takes no divider. The row joins the lines by the theme's `divider` glyph, and cuts the joined line at its width with `more`. Where `more` does not fit, the row draws empty. `gap` does nothing in it. A click lands on the child under it, on its first line, at the column of the Part's lines as drawn at the row's whole width. A nested child takes a click only on its own line, never on a divider or a later child. A click on a divider, or past the cut, lands on nothing. Its width, when its parent measures it, is the joined line's, measured apart, so that measuring leaves no cells to click.
- **A node can take no cells, its box included**: a named Layout or a `first` with no line to draw, and a node hidden by `unless`. Its parent lays out its other children as if it were not there, so no gap is kept for it. A node has a line to draw while a Place in it does. An `unless` that names a Layout it is in finds no lines there, so it always ends.
- **Only a float draws over what it covers** ([ADR 3](../adr/0003-only-a-float-draws-over-what-it-covers.md)). The float is centred across, at the top, the bottom or the centre, and 4 cells narrower than what it covers, at most 80, unless `at.width` says. The layout keeps the cells that a click and the wheel land on, the topmost first: a float's Places, then its whole box, which hits nothing, then what it covers. So a click on a float's border reaches nothing beneath it, and a float inside a float stays on top. A cursor that it covers is not drawn. A float with a line to draw gives its node a line to draw, and its height and width when the node takes what its lines need: the float's width, with its margin, or `at.width`. A node of a fixed size counts as that size when its parent measures what its lines need, so a float holding a `{ fixed: n }` node is as high as `n`, not as what the node holds.
- **`clickFocus: false` holds for each Place inside the node** ([ADR 5](../adr/0005-a-click-takes-the-keys-only-where-a-person-types-or-picks.md)). A click there reaches the Part and its Place's actions, and moves no Focus. A Place that has the Focus keeps it. Each hit that the layout makes keeps whether a click on it moves the Focus, as it keeps whether the mouse reaches it. The Chat's transcript node is `{ place: 'transcript', size: 'fill', clickFocus: false }`.
- **`mouse: false` holds for each Place inside the node.** A click or the wheel on such a Place does nothing, and moves no Focus. It does not go to what is beneath.
- **Edges** are a named table: `binnacle:packages/binnacle/src/core/theme.ts#edges`. A box's borders are drawn in the theme's `border` Tone, and its default edge, padding and gap are the theme's ([Kit](kit.md)).
- **A row ends where its style does.** The display clears each row to its end, so the blanks at a row's end are not written while no style is open. The layout follows each style to where it is closed, as a border closes only what it opened.
- **Each registration is held apart**: a Part placed, a Layout, an edit, a Screen shown, a named Model and a theme layer. When a plugin unloads, only its own registrations go, even when another plugin registered the same object, and the newest one left wins again. A plugin that registers while it unloads holds nothing: the call throws Cordis's error, and the screen does not change.
- **A built-in's registration ranks beneath an author's**, whichever loads first, so an author's plugin wins on every start. Among the built-ins, and among the authors, the newest wins. The core reads the registering plugin's fiber, and walks up to the first that has a loader entry, as the loader's `locate` does (`dsh:vendor/loader/src/index.ts#Loader`). A registration is a built-in's when that entry's `name` is `binnacle` or begins with `binnacle/`: each row of the bundle's patch, and no list kept by hand. A plugin with no entry ranks as an author's. This holds for every registration, an action and a binding too.
- **A Place follows its Part's cursor as the Part's `follow` says.** With `'end'`, the default, the Place shows its end, or the rows the wheel scrolled to, and a cursor outside them is brought to the nearest edge for that draw: below to the bottom row, above to the top row. So the transcript keeps its Marked event's header on the top row. With `'least'`, the rows that a draw shows are kept as the Place's scroll, so the next draw starts from them, and the cursor moves them only as far as its row needs. A `'least'` Place does this with the Focus or without it. So a List keeps its mark in view while the person types in another Place. The terminal's cursor is drawn only at the Part with the Focus.
- **A scroll by an author wins over the cursor until the cursor moves.** The Place with the Focus shows the row of its Part's cursor, however the wheel scrolled it. After `binnacle.scroll(place, pages)`, the Place shows the rows paged to, and the cursor is not drawn while its row is out of view. Once the Part's cursor is at another line or column than when the page was made, as when a key moves it, the Place follows the cursor again. The wheel ends a page, and the Place follows the cursor, as before.
- **The core counts the lines that a Place shows**, a wrapped line once, from the last draw, so that a List's page is as many items as its Place shows. An author reads it with `binnacle.linesShown(place)`, as the List and the offer of commands do.
- **The core tells where the Focus was last moved**, by a person or an author, on the Screen on view, and keeps it after it forgets the move. A Place that stops taking keys loses the Focus at the next draw, and that draw can come before a watcher of the change that hid the Place. So the Requests view knows whether its Line or its Choices had the Focus, and leaves a Focus that a plugin moved. An author reads it with `binnacle.focusMovedLast()`, as the view does.
- **The clock pulls** (`binnacle:packages/binnacle/src/core/clock.ts#startClock`). A read of `now` notes itself, and starts the timer when it is stopped. A second after the clock last changed, it changes again if `now` was read since then, and else it stops. So a Part that names it is drawn again, reads it again, and keeps it ticking, and once nothing on screen reads it, nothing ticks. A read outside a draw counts as one: a tick too many costs one draw. `now` is read from the time at each read, so a clock that was stopped is never late. The timer is the core's, and stops when the core unloads. `set` on the clock does nothing. The core names it as a built-in, so an author's Model named `clock` ranks above it.
- **The turn follows dsh** (`binnacle:packages/binnacle/src/core/turn.ts#startTurn`). Its `startedAt` is the time of the session's newest `turn/start`, so a queued turn, which starts while the agent runs, sets it again. Until that event comes, it is when the agent's status became `running`, and it is `undefined` once the status is anything else. When the session opens on an agent that runs, it reads the newest turn that has not ended from the session's events. A stored session has no agent, so no turn. The core names it with `clock`, as a built-in (`binnacle:packages/binnacle/src/core/models.ts#coreModels`), and `set` on it does nothing.
- **The alternate screen.** binnacle draws on it, and the layout keeps the composer at the bottom.
- **Styled lines.** A Part's lines may carry colour and style. The core takes out every other control sequence. A plugin makes Untrusted Text plain with `binnacle:packages/binnacle/src/core/view.ts#toPlainText`, and a Part says where its cursor is.
- **Wide content wraps**, as in pi.
- **One owner of the terminal**, `binnacle:packages/binnacle/src/core/host.ts#Host`, so a crash, a suspend and an unload each give it back once. `binnacle:packages/binnacle/src/core/capture.ts#capture` holds back what other code writes while binnacle draws.
- **Quitting ends the process.** When binnacle asks dsh to exit, with ctrl+c twice or when the session fails to open, it also asks the process to end 5 seconds later, with the exit code dsh set, by a timer that keeps nothing alive. dsh's `appExit` clears its own forced exit once it has disposed (`dsh:apps/cli/src/process-shutdown.ts#createProcessShutdown`), and a socket left open, such as a proxy's, then holds the process. A process that ends on its own ends at once. 5 seconds is dsh's own grace for disposal, so binnacle never cuts that short.
- **The session.** `binnacle:packages/binnacle/src/core/session.ts#openChat` opens the Chat's session as dsh's headless bundle does: on `dsh-base`, with no preset, on the default model. A stored session is read once.
- **`binnacle/testing` is the harness of binnacle's own tests** (`binnacle:packages/binnacle/src/testing/index.ts#mount`). It mounts the core on an emulated terminal, `@xterm/headless`, with a fake process, streams and clock, and a fake agent of dsh's that records what it is sent. It loads the built-ins as rows of a Cordis loader named `binnacle/plugins/<name>`, so they rank as a profile ranks them, and an author's plugins as rows of their own after them. It holds the core's terminal and clock, so one mount is open at a time. The core's own tests use the harness beneath it, `binnacle:packages/binnacle/src/testing/core.ts#mountCore`, which starts the core before dsh is ready.
- **Hot reload is off** in the bundle's patch, until the core stays up while its plugins reload.
- **pi-tui** is copied, with credit, under `packages/binnacle/src/terminal/`: its input decoding, text width, terminal I/O, editor and input, and how it draws an exact colour.
